ShaderBox 用户指南

从渲染器的工作原理，到每一个节点端口的含义——这份手册详细讲解 ShaderBox 的全部创作机制。

1ShaderBox 是什么

一款着色器创作应用：编写的是逐像素运行的图形程序，普通人也能上手。

着色器（Shader）是一段「对画面上每个像素同时执行」的小程序。你不需要理解整幅画面， 只需要告诉 ShaderBox：「坐标为 (x, y) 的这个像素，此刻应该是什么颜色？」 剩下的交给 GPU——它会让画面中数百万个像素同时执行你的规则，因此实时动画也毫无压力。

ShaderBox 提供两种等价的创作方式，可以单独使用，也可以混搭：

  • 节点图编辑 — 拖拽节点、连上端口，画面逻辑一目了然，无需写代码。节点图会自动编译成 GLSL。
  • GLSL 代码编辑 — 直接书写着色器代码，带语法高亮、自动补全、实时错误提示，与节点图双向同步。

2快速上手

五分钟做出你的第一个作品。

  1. 创建项目 — 在首页点击「新建项目」，为它起个名字。
  2. 打开编辑器 — 点击项目卡片进入，你会看到默认的渲染画面。
  3. 进入 Image 通道 — Image 通道决定最终呈现的画面，大多数创作从这里开始。
  4. 搭建第一个节点图 — 右键空白处新建节点：用「输入」节点取 UV 坐标，用「数学计算」节点做一点变化，再连到「输出」节点，画面立刻改变。
  5. 设为壁纸 — 满意后通过导出菜单设为动态壁纸或保存截图。
💡项目会自动保存；几乎所有节点操作都可以用 Ctrl+Z 撤销，大胆尝试。

3渲染管线

理解 ShaderBox 如何把你的编辑变成屏幕上的画面。

每一帧，渲染器按固定流程执行：先加载你的编辑模型，然后按顺序运行各个渲染通道， 每个通道的输出保存为一张 GPU 纹理，供下游通道读取，最终由 Image 通道输出到屏幕。 

ShaderEditorModel（你的编辑内容）
  │
  ▼ RenderEnv.loadModel()
  │
  ├──→ PresetRenderer    ← Image 通道：最终画面，渲染到屏幕
  │
  ├──→ BufferRenderer    ← Buffer A/B/C/D：离屏渲染到纹理
  │                          输出通过 ChannelSlot 提供给其他通道
  │
  └──→ CubeMapRenderer   ← CubeMap 通道：6 个面分别渲染为立方体贴图

  通道输出 ──→ ChannelSlot（OpenGL 纹理）──→ 下游通道采样读取

执行顺序

通道按 BufferA → BufferB → BufferC → BufferD → CubeMap → Image 的顺序执行。 因此 Image 通道可以读取所有 Buffer 的结果，而 BufferA 读不到排在它后面的 BufferB—— 需要多个中间步骤时，请按依赖顺序分配到 A→B→C→D。

4渲染通道详解

一个作品由若干「渲染通道（Render Pass）」组成，每个通道是一段独立的着色器程序。

通道作用输出典型用途
Image 最终画面，每个作品必有且只有一个。渲染结果直接显示在屏幕 / 壁纸上。 屏幕 合成所有中间结果，输出最终颜色
Buffer A–D 离屏渲染的中间缓冲。每帧的结果会保留到下一帧，因此可以做「反馈」效果。 一张纹理（分辨率可在设置中调整） 流体模拟、轨迹拖尾、迭代计算、延迟合成
CubeMap 立方体贴图通道，对立方体的 6 个面分别执行一次着色器。 一张立方体贴图 环境反射、天空盒、全景效果
Common 不是渲染通道，而是存放各通道共用 GLSL 代码的工具函数区。 — 放公共函数、常量定义，避免重复

Buffer 通道的反馈机制

Buffer 通道「本帧结果 = f(本帧输入, 上一帧结果)」的特性是 ShaderToy 类效果的核心。 例如把上一帧画面偏移 1 像素后与新内容叠加，就能得到拖尾；反复采样自身扰动， 就能得到类流体效果。

通道操作

  • 切换 — 点击通道标签切换当前编辑的通道。
  • 复制 / 重命名 / 交换 / 删除 — 在通道菜单中操作。交换用于调整执行顺序。
💡Buffer 通道的分辨率独立于屏幕分辨率，在设置中调低可以大幅提升性能，且不影响 Image 通道的清晰度。

5通道间的数据流

通道不是孤岛：它们通过「通道槽位」交换渲染结果。

每个渲染通道在渲染管线中对应一个通道槽位（ChannelSlot）， 本质是一张 OpenGL 纹理。下游通道通过「纹理采样」节点读取槽位内容， 就像读取一张普通图片一样。 

BufferA 渲染 ──→ ChannelSlot A ──┐
BufferB 渲染 ──→ ChannelSlot B ──┼──→ Image 通道用「纹理采样」节点
BufferC 渲染 ──→ ChannelSlot C ──┤    读任意槽位作为输入
BufferD 渲染 ──→ ChannelSlot D ──┘

读取其他 Buffer 的输出时，使用纹理采样节点并把纹理源选为对应的 Channel（A/B/C/D）即可。这也是跨通道传值、做多 pass 效果的唯一方式。

6编译系统

你的节点图 / 代码在被 GPU 执行前会经历编译，了解它能帮你快速排查问题。

编译状态

状态含义
编译中正在把节点图转换成 GLSL 并提交 GPU 编译，画面会短暂保持上一帧。
成功编译通过，渲染器开始用新代码逐帧渲染。
失败编译出错，错误列表会标明每个错误的行号与描述，点击可定位。

节点图 → GLSL 的过程

  1. 拓扑排序 — 沿连线解析节点依赖，确定每个节点代码的先后顺序。
  2. 逐节点生成语句 — 每个节点输出对应的 GLSL 表达式或语句（详见节点参考）。
  3. 合并为完整着色器 — 注入 uniform 声明与依赖的工具函数，生成完整程序。
  4. GPU 编译 — 交给 OpenGL 编译链接，出错则回读错误信息。

导出目标

除内置 GLSL 渲染外，节点图还可以导出为 Godot 4.x 的 .gdshader（canvas_item）着色器，用于在 Godot 引擎中实时刷新使用。

7内置输入变量

渲染器在每帧自动注入这些变量，「输入」节点可以直接取用。

变量类型含义典型用法
uvVec2当前像素的归一化坐标，画面左下角为 (0,0)，右上角为 (1,1)几乎所有效果的位置依据
iTimeFloat运行时间（秒），持续增长做动画：sin(iTime)
iResolutionVec3画布分辨率。x = 宽，y = 高（单位像素），z = 宽高比宽高比校正、按比例布局；取 uv = fragCoord.xy / iResolution.xy 即归一化坐标
fragCoordVec4当前像素的窗口像素坐标（非归一化）需要像素级精度的计算
iMouseVec4鼠标 / 触摸状态。xy = 当前位置（像素坐标，拖动时更新），z = 按下标志（按住为 1，松开为 0），w 未使用交互效果；用 iMouse.z 判断是否按住
iFrameInt当前帧号，每帧 +1逐帧动画、定时触发
iTimeDeltaFloat上一帧到本帧的时间间隔（秒）与帧率无关的速度计算
iFrameRateFloat当前帧率（FPS）性能监测、自适应质量
💡「输入」节点还支持自定义输入：填入任意变量名或表达式，适合配合自己写的 GLSL 代码使用。

8节点图基本操作

节点图编辑器的常用手势与快捷键。

  • 新建节点 — 空白处右键（移动端长按）；桌面端按 Space 在视口中央打开。
  • 移动 / 缩放视图 — 拖拽空白平移，滚轮或双指缩放。
  • 连线 — 从输出端口圆点拖到输入端口；端口类型匹配才能连上，拖拽时会对齐最近的兼容端口。
  • 断开 — 把连线一端拖离后松手。
  • 内嵌常量 — 很多节点的输入端口即使不连线也能工作：点开端口可以直接填一个常量值。
  • 属性编辑 — 点击节点上的数值 / 下拉框 / 颜色块修改参数。
  • 预览 — 任意节点可开启输出预览，从输出端逐级往前看，快速定位画面异常的环节。

9数据类型与端口

连线时两端的类型必须兼容；端口颜色就是类型提示。

数据类型

类型含义说明
Float标量单个数值，如 0.5、时间、距离
Int整数帧号等整数值
Bool布尔真 / 假，用于条件判断
Vec2二维向量两个分量，如 UV 坐标 (x, y)
Vec3三维向量如颜色 RGB、空间坐标 xyz
Vec4四维向量如带透明度的颜色 RGBA
Mat2/3/4矩阵旋转、缩放等变换

SamplerCube立方体采样器立方体贴图，用于环境反射

颜色约定

向量分量按 rgba 顺序命名：Vec2 的两个分量叫 r、g（即 x、y），Vec3 是 r、g、b，Vec4 是 r、g、b、a。分量数（1/2/3/4 个字母）决定了结果类型是 Float / Vec2 / Vec3 / Vec4。

节点分类

分类颜色节点
Value（值）红输入、常量、迭代索引、读取累加器
Converter（转换）蓝数学计算、条件、分量重排、向量合成 / 分解
Texture（纹理）橙纹理采样、程序化纹理
Endpoint（端点）紫红输出、组输入 / 组输出、累加器初值 / 写入、中断
Complex（复合）绿节点组、自定义函数

用法示例

「输入 uv」→「数学计算 sin」→「输出」，就会得到随位置波动的条纹——这是理解「逐像素编程」的第一课。

常量 Constant

Value
输入端口：无　·　输出：Value Float / Vec2 / Vec3 / Vec4

输出一个固定数值。选择类型后逐分量填写，如 Vec3 (1.0, 0.5, 0.0) 是一个橙色。

要点

  • 可选择以 uniform 形式输出：常量变成可由外部（如 AI 工具、导出目标）调整的参数，而不是硬编码进代码。
  • 单个不常改的数值，用端口内嵌常量（◇）往往比单独放一个常量节点更简洁；需要多处共用同一个值时再抽成常量节点。

分量重排 Swizzling

Converter
输入：Input ◇ Vec2 / Vec3 / Vec4　·　输出：可动态增删的多个端口

从向量中按顺序抽取分量，相当于 GLSL 的 .xyz 写法。每个输出口用 rgba 组合命名，名字长度决定输出类型：r → Float，rg → Vec2，rgb → Vec3，rgba → Vec4。

用法示例

纹理采样输出 RGBA，但你只要亮度感——加一个 Swizzling，输出端口设为 rrr（三个分量都取 R），就得到灰度图。

向量合成 Vec Compose

Converter
输入：可动态增删的多个端口 ◇　·　输出：Output Vec2 / Vec3 / Vec4

把若干小分量拼成一个大向量（如 vec3(a, b, c)）。输入端口按累计维度自动命名为 r、g、b、a，可以是 Float 或更小的向量（如 Vec2 + Float → Vec3）。

用法示例

把三个 Float 端口分别设为 1.0、0.4、0.2，输出即颜色 (1.0, 0.4, 0.2)，接进「输出」节点即可上屏。

向量分解 Vec Decompose

Converter
输入：Input ◇ Vec2 / Vec3 / Vec4　·　输出：R G B A（均为 Float）

把向量拆成单分量，输出口数量与输入维度一致。典型用途：把 UV 拆开，对 x、y 分别做不同处理后再用「向量合成」拼回去。

纹理采样 Texture

Texture
输入：随采样函数（坐标 ◇ + Lod ◇）　·　输出：Output Vec4（RGBA）

读取一张纹理的颜色。纹理源支持三类：

纹理源坐标类型说明
Sampler2DVec2普通 2D 图片 / CubeMap 之外的大部分纹理
Sampler3DVec33D 纹理
Channel（Buffer 槽位）Vec2读取 Buffer A–D 的渲染结果，实现跨通道取值
None—无纹理，恒输出 vec4(0)，用于占位

采样函数

函数输入输出说明
Texture（常规采样）坐标Vec4按 UV 采样，自动带 mip 与滤波。99% 的情况用它

程序化纹理 Procedural Texture

Texture
输入：随纹理类型 ◇　·　输出：Output（Float 或 Vec3）

用算法直接生成随机数与噪声，无需任何图片资源。所需 GLSL 函数会自动注入编译结果。

类型输入输出说明
Hash 1→1FloatFloat单值哈希，输入相同则输出恒定（0~1 随机感）
Hash 1→3FloatVec3一个数生成三个随机数
Hash 2→3Vec2Vec3按坐标生成随机颜色 / 随机数
Hash 3→3Vec3Vec3三维随机数
Simplex Noise 2DVec2Float二维单纯形噪声：连续、平滑、无网格感。云、火焰、地形的基础
Simplex Noise 3DVec3Float三维版本；把 iTime 当第三维输入即可得到流动的噪声
VoronoiseP Vec2，U / V FloatFloat可调噪声：U 越大越接近「网格块状」（Voronoi 感），V 越大越平滑（噪声感），两者之间连续过渡

用法示例

「输入 uv」×3 →「Simplex Noise 2D」→ 输出，得到流动的黑白云纹；把噪声结果接进「数学计算 mix」的 C 端口做两色渐变，就是最经典的噪声调色。

输出 Output

Endpoint
输入：Value ◇ Vec4（RGBA）　·　输出：无

节点图的终点：写进该通道画面的最终颜色。每个通道的图里都有且必须有一个输出节点，最终显示的颜色就是连到它上面的 RGBA。

⚠️输出的 alpha 分量决定透明度。壁纸场景下 alpha < 1 可能露出下层内容。

节点组 Node Group

Complex

把一段子图封装成一个可复用的「大节点」。编译时整组会变成一个 GLSL 函数，调用它就像调用普通函数一样。

三个配套节点

节点位置作用
组输入 Group Input组内部声明组的输入端口；这些端口会出现在外部「节点组」节点的左侧
组输出 Group Output组内部声明组的输出端口，把组内结果交还给外部
节点组 Node Group任意处引用某个已定义的组，作为一个节点使用；重命名节点会同步改组名

用法

  1. 选中一段节点，选择「创建组」（或先建组再往里填节点）。
  2. 进入组内部，添加「组输入」「组输出」，把内部逻辑与端口连好。
  3. 回到上层，组已经变成一个节点，可在同项目内重复摆放。
💡常用套路：把「噪声 + 调色」封装成组，多个项目里反复调用，图面只剩一条主干线。

自定义函数 Func Code

Complex
输入 / 输出：由所选函数定义动态决定（可增删，自动命名）　·　各端口均支持 ◇

调用一段自己维护的 GLSL 代码块。与节点组不同，它没有内部节点图，而是直接写 GLSL 函数体；输入输出端口的数量与类型由函数签名决定。

适用场景

  • 从 ShaderToy 抄来的工具函数（raymarching、SDF 等）直接包成一个节点用。
  • 节点图难以表达的复杂算法（比如整段光线步进）。
  • 函数会被注册进编译结果，调用处生成 funcName(args...)。

循环与累加器 Loop / Accumulator

Complex

循环节点把一段子图按次数重复执行，等价于 GLSL 的 for 循环。循环组内部由 5 个配套节点协作：

节点分类作用
迭代索引 IterationValue输出当前循环到第几轮（0 开始，Float）。循环内取用
累加器初值 Accumulator InitialEndpoint定义每个累加器的初始值，循环开始前执行一次
读取累加器 Accumulator ReadValue读取上一轮迭代写入的累加器值（第一轮读到初始值）
写入累加器 Accumulator WriteEndpoint更新累加器，供下一轮读取。循环结束后保留最终值
中断 BreakEndpoint输入一个 Bool，为真时提前跳出循环（if (cond) break;）

理解累加器

累加器就是循环里的 acc 变量：初值节点决定它从什么开始， 每轮先「读取」拿到上一轮的值参与计算，再用「写入」保存这一轮的结果。 典型流程：初值 0 → 每轮 读取 + 累加 → 循环结束输出总和。 配合「迭代索引」可做级数求和、多光源叠加、迭代 SDF 等效果。

⚠️循环次数过多会显著拖慢渲染。能用数学公式（如 pow、mix）代替的迭代，优先用公式。

11内置 GLSL 函数

节点库自带的工具函数，使用对应节点时自动注入，也可以在代码编辑器 / 自定义函数里直接调用。

函数签名说明
sn_hash11Float → Float整数哈希，返回 0~1 的伪随机数
sn_hash13Float → Vec3一入三出哈希
sn_hash23Vec2 → Vec3按坐标生成随机数（sin 点积风格）
sn_hash33Vec3 → Vec3三维哈希
sn_permute3 / sn_permute4Vec3/4 → 同单纯形噪声内部使用的置换函数
sn_snoise2DVec2 → Float2D 单纯形噪声（依赖 permute3）
sn_snoise3DVec3 → Float3D 单纯形噪声（依赖 permute4）
sn_voronoise(Vec2, Float, Float) → Float可调 Voronoi/噪声混合（依赖 hash23）；U 控制块状度，V 控制平滑度

12常见问题

端口连不上？两端数据类型必须兼容（端口颜色相同或可隐式转换）。用「向量合成 / 分解」「分量重排」节点转换类型。
画面全黑？检查「输出」节点是否连线、alpha 是否为 0；用节点预览从输出端逐级往前排查。
画面卡顿 / 发热？调低 Buffer 通道分辨率；减少循环迭代次数；噪声节点避免在高分辨率下逐像素多重采样。
Buffer 读不到另一个 Buffer？通道按 A→B→C→D→Image 顺序执行，只能读到排在自己前面的通道。调整通道顺序（交换功能）。
动画不动？确认有节点用到了 iTime。静态图永远静止，加入时间输入才会随帧变化。
编译报错看不懂？错误信息含行号与描述；节点图出错时可切代码视图对照。也可以让 AI 助手帮忙修复。
删除的项目能找回吗？不能。删除不可恢复，重要作品建议先复制备份。

13隐私政策

本地优先：应用本身不收集个人信息。

  • 本地数据 — 项目、代码、导入的资源与设置都保存在设备上，卸载或清除应用数据即可删除。
  • 可选网络功能 — 只有主动使用 AI 助手或 ShaderToy 浏览/导入时才会联网；请求会发送到你配置的 AI 服务或 shadertoy.com。
  • 无广告与统计 — 应用不包含广告、行为统计或崩溃上报 SDK，也不要求注册账号。
